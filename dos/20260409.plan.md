# `jadelai.top` 门户首页计划

## Summary
构建一个部署在 `jadelai.top` 根域名的静态门户页，作为现有子站 `bca.jadelai.top`、`doc.jadelai.top`、`animal.jadelai.top` 的统一入口。页面采用“目录列表式门户 + 冷静灰蓝”风格，站点内容由单独配置文件驱动，后续新增子站时只改配置，不改页面结构。

## Implementation Changes
- 项目形态：纯静态 `HTML/CSS/JS`，不引入前端框架；`Pixi` 仅负责本地开发与检查任务。
- 目录建议：
  - `index.html`：门户页面骨架
  - `assets/styles.css`：统一主题变量与页面样式
  - `assets/app.js`：读取站点配置并渲染目录列表
  - `data/sites.json`：站点注册表
  - `scripts/check_sites.py` 或等价轻量脚本：校验配置字段完整性
  - `pixi.toml`：定义 `serve`、`check` 等任务
  - `.gitignore`、`README.md`：忽略规则与维护说明
- 页面结构：
  - 顶部仅保留站点标题、副标题和简短说明
  - 主体使用纵向目录列表，每条包含 `名称`、`描述`、`域名/链接`、`进入` 按钮
  - 视觉以灰蓝系 CSS 变量统一颜色、边框、悬停态与按钮风格，避免花哨装饰
- 配置接口：
  - `sites.json` 使用数组顺序作为展示顺序
  - 每项至少包含：`id`、`name`、`url`、`description`
  - 不做网页内编辑，不做自动发现，不做账号或后台逻辑
- 工程任务：
  - `pixi run serve`：本地启动静态预览
  - `pixi run check`：校验 `sites.json` 结构与必填字段
- Git 边界：
  - 先把当前目录初始化为 Git 仓库，再在清晰边界内提交门户基础骨架
  - `.superpowers/`、缓存、临时产物不纳入版本控制

## Public Interfaces / Types
- 站点配置文件是本项目的核心维护接口，推荐形态：
  ```json
  [
    {
      "id": "bca",
      "name": "BCA",
      "url": "https://bca.jadelai.top",
      "description": "生信分析站点"
    }
  ]
  ```
- JS 渲染逻辑只依赖这一配置结构；新增站点的标准流程是“在 `data/sites.json` 新增一个对象并运行 `pixi run check`”。

## Test Plan
- 页面能正确渲染现有 3 个站点，点击后跳转到对应子域名
- 新增第 4 个站点配置后，无需改页面代码即可自动显示
- `sites.json` 缺少必填字段或 URL 非法时，`pixi run check` 明确失败
- 桌面端与移动端都保持可读；列表项、按钮、间距不破版
- 根域首页可作为 Cloudflare 静态部署入口，且不影响现有子域站点

## Assumptions
- 本轮范围只做“门户首页”，不包含在线后台、登录、权限、分析统计
- 当前目录还不是 Git 仓库；实施时默认先初始化 Git，再开始受控改动
- Cloudflare 域名与根域发布动作属于部署环节，本计划只覆盖项目代码与本地可验证结构
- 站点展示顺序以 `sites.json` 中的书写顺序为准，不额外设计排序系统
